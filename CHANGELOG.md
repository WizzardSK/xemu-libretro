# Changelog of the libretro core

What changed in the libretro core of this fork, newest first. Changes that come with a merge of upstream xemu are in upstream's own history; a merge is noted here with the upstream version it brought in.

## Unreleased

- Patch Manager: the 16:9 database of XboxGraphicalPatches' OgXHD tool (wdb.dat) is built in, 90 games not all in its 16:9 patch folder (Splinter Cell and Pandora Tomorrow, House of the Dead III, Crazy Taxi 3 High Roller and others). Each is listed by title ID as "(16-9 Widescreen, OgXHD)", off by default, replaces every place its bytes are found as OgXHD does, and makes Aspect Ratio Auto 16:9 like the other widescreen patches (NNshi).
- Sega Chihiro > Steering Response: Logarithmic puts the left stick's steering on a curve, less of the turn around the centre and steeper towards full lock, so a stick steers the racers less twitchily (OutRun 2, OutRun 2 SP, Maximum Tune 1 and 2, Crazy Taxi 3, Ollie King). Steering Effect (Cubic, strong, or Square, weak) and Steering Inner Zone (5 to 50%, 25% by default) set its shape and show only with it on. Linear, as before and as in standalone, by default (NNshi).
- Aspect Ratio Auto: 16:9 also when a patch with Widescreen or 16-9 in its name is on in the Patch Manager, whatever the console's widescreen setting and the 16:9 list (NNshi).
- Aspect Ratio Auto: a game started after another one in the same RetroArch got the aspect of the one before, and kept it: Ninja Gaiden Black came up 4:3 four times in six after a 4:3 game. The core told RetroArch the aspect only when it changed from what it had last told it, and the first one, at load, came from the previous game's title. It now forgets that game's title and aspect when it closes (NNshi).
- Vulkan: with Vulkan Fast Paths on All, RalliSport Challenge 2 stopped on an assertion (is_uniform && is_compressed, vsh.c) when loading a race. With All, a vertex program's shaders are prepared as soon as the game uploads it, from the vertex arrays of the last draw, and one of their masks already had the next draw's formats: an attribute could be both a constant and a packed array, which no draw has. They are now all taken from the vertex arrays as the next draw will set them. Conker crashed the same way. Vulkan Fast Paths is All by default again, as in standalone (NNshi).
- Four NV2A fixes from upstream xemu 0.8.137: surface colour/zeta offsets given as RAM addresses (f78d85efb45), PFIFO CACHE1_DMA_CTL always valid (5906e2b556a), Y16 texture formats (ac72edfc2bc), passthru texture coordinates clamped (e7a681cf7f9). They do not fix Splinter Cell's flickering FMVs, which flicker in upstream 0.8.139 too (NNshi).
- Windows: the CPU, GPU (PFIFO) and audio frame threads run above normal priority, as in xemu-macos's Windows build. At normal priority they share their cores with every other thread of the system and of the frontend; the same scene ran at 32 or 46 fps from one run to the next (Splinter Cell, NNshi).
- MSPF Overlay is now Performance Overlay, with two labelled lines: FPS, the frames per second the game shows (standalone xemu's FPS from its video debug view) with two decimals, over its last 60 frames, so a 59.94 Hz game reads 59.94; and GPU, the rate from the render time that was the overlay's only line (NNshi).
- NFL Fever 2004 is on the list of games that render 16:9 with Widescreen on (NNshi).
- Vulkan: Virtua Cop 3 and NFL Fever 2004 stopped on an assertion (zeta_covers_color, surface.c) since a larger depth buffer stays bound for a smaller colour target. The kept depth buffer could stop covering the colour target: a draw bound a colour target it did not cover (another anti-aliasing mode, a swizzled target, or one larger than it), or the game switched to a swizzled target, which marks both bound surfaces swizzled. The depth buffer is now bound again for the colour target in both cases, as after a colour change between draws (NNshi).
- RDPMC (reading the CPU's performance counters) gives 0 instead of an invalid-instruction fault, as there are no counters emulated; on the console it never faults, and programs that read them (the XDK's FastCPU sample) crashed. From xemu's open pull request 2987 (EqUiNoX-Labs) (NNshi).
- x87: a double (FLD m64) loaded while the game has set single precision keeps its full precision; precision control rounds only the results of arithmetic, and the core rounded the loads too. NFL Fever 2004 gets past its loading. From xemu's open pull request 2951 (korzewarrior) (NNshi).
- R: Racing Evolution draws at native resolution whatever Internal Resolution Scale says, in standalone xemu too, until the scale is changed while it runs. With a scale above 1x the core now sets the same scale again once, 2 seconds after the game has started, which makes its surfaces again at that scale (NNshi).
- Savestates: with APU DSP Emulation on, the sound after a load was now and then garbled until the state was loaded again. The APU started running again while the state was still being loaded, its DSPs on their state from before the load writing into the loaded RAM; it now stays paused until the game runs again (NNshi).
- Vulkan: a texture the CPU writes to after a draw of the same frame has sampled it is checked again at its next bind; the change showed only from the next frame on. Fixes the missing bloom in Jade Empire. From parallel-xbox (32caea67) (NNshi).
- Savestates hold the whole machine in RetroArch's state file: the CPU, every device and the 64 MB of RAM as QEMU's migration stream (about 70 MB), written into RetroArch's buffer and read from it, so slots and state files work as in other cores. They used to be a snapshot inside the HDD image, one for all slots, with only a header in the state file. The HDD is not in a state: one loaded after the game has written to the disk since finds the disk as it is now. States of earlier builds don't load. After parallel-xbox's savestates (NNshi). The core info says the core has savestates (basic: no netplay or run-ahead).
- R: Racing Evolution is on the list of games that render 16:9, so System Aspect Ratio's Auto gives it 16:9 with Widescreen on (NNshi).
- New option Video > Subpixel Offset Scaling, after Internal Resolution Scale (OFF by default): with a scale above 1x the picture is moved by a fraction of a pixel so the higher resolution's pixels line up with the original ones. It fixes ghosting and seams in some games (Jade Empire, Blinx) and breaks others (Splinter Cell). It takes effect while the game runs. From upstream xemu's open PR #3065 (NNshi).
- Crop Vertical Overscan: Panzer Dragoon Orta, Soulcalibur II and R: Racing Evolution are on the Auto list (NNshi).
- The DAC's gamma ramp a game sets (the NV_USER_DAC palette) is applied to the picture, after the video overlay, on both renderers; it was ignored, and Baldur's Gate: Dark Alliance looked washed out. A ramp that leaves colours as they are costs nothing. After parallel-xbox (a0ee82d8), adapted to this core's display paths (NNshi).
- Point sprites whose size the game's vertex program sets are scaled with the internal resolution, as those of the fixed pipeline already were: upscaled, they came out at native size (Baldur's Gate: Dark Alliance's shadows). From parallel-xbox (e161cd08) (NNshi).
- In a game that flips after nearly every vblank, the core waits after the vblank until the game's flip for it is done (at most 8 ms) before it takes the picture: OutRun 2 NTSC-J completes its flips up to 4 ms after the vblank, and about one run in nine showed the previous frame again. Games at 30 fps or less are not waited for (NNshi).
- MSPF Overlay (Video, last, off by default): shows in the top left corner the frame rate the game could reach, from the time it takes to draw a frame (standalone xemu's MSPF), averaged over the last 60 frames and updated every 20, with two decimals; on both renderers, and it can be switched while a game runs. While it is on, the core also writes its 300-run frame lines (the guest's flips against the frontend's runs) to RetroArch's log; off, it no longer writes them (NNshi).
- Signed G8B8 textures (bump and distortion data, as in Ninja Gaiden's water) are decoded before they are filtered, within and across mip levels, and the combiner's per-channel sign flags are honoured; from parallel-xbox (NNshi).
- Audio Volume Limit (%) is gone: RetroArch has its own volume control (NNshi).
- Crop Vertical Overscan: Breakdown is on the Auto list (NNshi).
- Vulkan: when a game draws to a smaller colour target over a larger depth buffer it already has, the depth buffer is kept bound instead of being written back to RAM and made again at the smaller size, so its contents are no longer lost between passes (GunValkyrie's dash showed broken graphics, #3, SteveDoido). Taken from parallel-xbox (f530f09b), which adapted upstream xemu's open PR #3096 (voorunde).
- New option Video > Crop Vertical Overscan, after Core Aspect Ratio: Auto (the default) or Off (as before). Some games draw a 448-line picture inside the Xbox's 480 lines, with black bars above and below; Auto crops 16 of every 480 lines at the top and at the bottom of the games on the core's list (Baldur's Gate: Dark Alliance I and II, Fallout: Brotherhood of Steel, The Bard's Tale, Combat Elite: WWII Paratroopers, Burnout 3 and Revenge, Dynasty Warriors 3, 4 and 5) and stretches the rest to the full height, without changing the aspect ratio. It takes effect while the game runs (NNshi).
- Burnout Revenge (both releases) is on the list of games that render 16:9, so System Aspect Ratio's Auto gives it 16:9 with Widescreen on (NNshi).
- New option System > System Language (Auto, Dashboard, English, Japanese, German, French, Spanish, Italian, Korean, Chinese, Portuguese; Auto by default, NNshi): the language the console's settings give games, set in the EEPROM at each start as System Aspect Ratio is. Dashboard keeps the EEPROM's; Auto is RetroArch's language where the Xbox has it, English otherwise. An EEPROM made in another language no longer needs the dashboard to change it (Good Dragon).
- System Memory's tooltip says it is the Xbox's: a Sega Chihiro always has its 128 MB (Akrido).
- Audio Thread's tooltip: the slow menu with Menu Frame Rate on Display Rate is only in RetroArch builds from before November 2026, which RetroArch fixed (Akrido).
- Trim HDD on Close: switched on in the menu and the content closed straight from the menu, it trims again without a restart; the core saw the change only at the next frame, which never came (Akrido).
- Patch Manager: XboxGraphicalPatches' 16:9 widescreen, 60 FPS and miscellaneous patches (140) are built into the core, with icup321's permission (XboxGraphicalPatches issue #16), and listed for their games next to the patches in system/xemu/patches, which still load and take a bundled patch's place when one has the same name (NNshi). `scripts/gen_bundled_patches.py` makes `ui/libretro-bundled-patches.h` from a checkout of that repository. The patches' options are now `xemu_zpatch_<hash>` (they were `xemu_patch_<hash>`), so that they come after the core's own options in RetroArch's .opt file: patches switched on before have to be switched on again.
- Core info: no longer marked experimental, and the hard disk image is listed as optional, as the core creates one when there is none (NNshi).
- Patch Manager: a patched game started again in the same RetroArch session gets its patches; every second start ran unpatched, as on Windows the first start's patched disc was still open in the drive and could not be made again (NNshi).
- APU DSP Emulation and DSP JIT are on by default: without the DSP the games' effects, reverb and much of their music are missing, and it costs no speed, as xemu's CPU thread is what limits it. Both are now (Restart), taken when the content starts: switched while a game ran, they garbled its sound (NNshi).
- xemu's pull request 3105 (MCPX improvements, raddad772), not merged upstream yet: the APU's voice processor matched to hardware tests - HRTF taps and ear routing, ParaEQ and I3DL2 filters, an 8-point resampler with the hardware's weights, envelope and volume curves, LFOs, and a voice-table overwrite and asserts on idle voices and other mix bins fixed (NNshi).
- Chihiro gun games on Mouse: the right button no longer also aims off the screen, through RetroArch's light gun Reload, which it binds to that button by default; Ghost Squad's action frees hostages again. Off the screen is aiming off the picture, or Reload bound to another button (gig71, issue 1).
- Chihiro games: RetroArch's controls list names the buttons by what they do in the game that runs, by its cabinet: the guns' Trigger, Reload, Pump Reload, Change Weapon, Action, Pedal, Fire Rate (with Light Gun Aim on Analog Stick); the racers' Steering, Gas, Brake, Gear or Shift Up and Down, View Change, Drive, Reverse, Jump; Ollie King's board and grabs; Gundam's two sticks and pedal; Start, Coin, Service, Test, Insert Card. Nothing is bound differently (NNshi).
- Trim HDD on Close empties the table of which game has which cache partition (sector 4) along with X, Y and Z: kept, it sent a game back to its partition as formatted, and the game, finding it empty, stopped on the dirty disc screen, in standalone too with that image (Akrido, RalliSport Challenge 2). An image a trim already left that way needs this table cleared or a fresh HDD.
- Chihiro gun games on Analog Stick: the stick moves the aim as fast across as up and down, at the speed it had up and down; across it crossed the whole width in the same time. New option Sega Chihiro > Stick Aim Sensitivity, after Light Gun Aim: 50 to 200% in steps of 10%, 100% by default (NNshi).
- New option Video > Anisotropic Filtering (Native, 2x, 4x, 8x, 16x; Native by default), the least anisotropic filtering a texture the game filters smoothly gets, on the fly, on both renderers; point-filtered textures stay as they are (xemu-project/xemu#409, NNshi).
- Patch Manager: IPS, BPS and Jay's Magic Patcher (`.jmp`) patches for a game's `default.xbe` in `system/xemu/patches/`, named after the game as XboxGraphicalPatches (`Game (16-9 Widescreen Patch).ips`) or Jay's Magic Patches (`Game {Widescreen} (All Regions) [Author].JMP`) name them, appear for that game in a new options category, Patch Manager (Restart), each off by default. A patch is the game's when its name matches the game's in its XBE or any of its title ID's names in xemu-project/xdb (`ui/libretro-xdb-titles.h`, from `scripts/gen_xdb_titles.py`). IPS patches are listed for North American releases only (the XBE's region), as XboxGraphicalPatches' broke PAL and Japanese ones; a BPS patch applies only to the XBE whose CRC it carries. A `.jmp` takes both of its forms: lines that write bytes at an offset, listed for the regions its `region=` line names, and pairs of lines that find bytes and replace them at the first place found, which apply only when every one is found (NNshi). The image stays as it is; the drive reads the patched XBE from a qcow2 overlay, `system/xemu/patched_disc.qcow2` (NNshi).
- Audio Thread's tooltip: with RetroArch's Menu Frame Rate on Display Rate, its default since October, RetroArch slows the paused menu for a core that uses the audio callback (from 240 to 30 fps for Akrido); Content Rate does not (NNshi found it). Audio Thread stays on by default, for the steady sound while shaders compile.
- Internal Resolution Scale is Internal Resolution Scale (Restart), taken when the content starts: raised while running above the scale it started with, it made RetroArch rebuild its video context and the core crashed (NNshi).
- New category Controls, after Audio: Rumble (Player 1) and (Player 2), on by default, turn off everything that rumbles that player's pad, the Xbox games' and a Chihiro racing game's force feedback; Analog Dead Zone (Player 1) and (Player 2), 0 to 30%, 10% by default, for both sticks, Xbox and Chihiro alike, with the rest of the travel scaled up to full (OutRun 2 stopped at a drive board error when the stick moved during its test) (NNshi).
- New option Audio > Audio Thread (Restart), on by default: the sound goes to RetroArch's audio thread as the APU mixes it, as standalone plays it, so it keeps going while frames stall, as while shaders compile (NNshi).
- The core carries xemu-dashboard's pre-formatted hard disk (`xbox_hdd.qcow2`, 1.6 MB, MIT: an unsigned dashboard and no Microsoft software) and writes it to `system/xemu/` when there is no HDD, so only the boot ROM and the BIOS have to be supplied (NNshi).
- Options: new defaults, unlike standalone's: Skip Boot Animation on, System Aspect Ratio 16:9, Light Gun Aim Analog Stick, Force Feedback Rumble 100% and Vulkan Fast Paths No Pipeline Libraries (RalliSport Challenge 2 and Conker crash with them). The System category is System (Restart), as its options are taken when the content starts, and its options no longer say (Restart) each; Trim HDD on Close is no longer Experimental and comes last there. Shader Cache (OpenGL) is gone: OpenGL's shader cache is always on, as Vulkan's is (NNshi).
- Options: Display Filtering is gone, it set what only standalone's UI reads (RetroArch's own filtering is what applies). Shader Cache is Shader Cache (OpenGL), as only the OpenGL renderer has it to switch (Vulkan's modules are always kept on disk). System Memory, Network Backend, Skip Boot Animation, Hardware FPU Emulation and AV Pack say (Restart), as they are read when the content starts. New in Audio, with standalone's defaults: DSP JIT (off), HRTF (on) and Voice Processor Threads (Restart, Auto) (NNshi).
- New option Video > System Aspect Ratio (Restart): Dashboard (as before), 4:3, 16:9 or Letterbox, set in the emulated EEPROM's video settings at each start, so a game that supports widescreen runs in it without going to the dashboard; the EEPROM file keeps the dashboard's own setting. Aspect Ratio is now Core Aspect Ratio, after it; its Auto follows the setting (NNshi).
- Aspect Ratio Auto: 16:9 when Widescreen is on in the dashboard's video settings and the game is one that renders 16:9 then, 4:3 otherwise and always on a Chihiro. The core knows the games by their Title ID, from a list of 200 games (226 releases) with 16:9 support; before, Auto waited for the game to switch the AV pack to widescreen, which games hardly do, and stayed at 4:3. The log says which Title ID runs, whether it is on the list and what the dashboard is set to (NNshi).
- New option System > Trim HDD on Close (Experimental), off by default: when the game is closed, the hard disk's cache partitions X, Y and Z are emptied (games format them again when they need them) and the image is rewritten without unused space, so `xbox_hdd.qcow2` shrinks. It needs as much free space as the image's data for a moment, and is skipped while the image holds a savestate, which would keep the space and be lost by the rewrite (NNshi, Akrido).
- The machine is stopped while RetroArch's menu is open or the content is paused, as standalone's Pause does it, once no frame has been asked for 50 ms (about 3 frames), and started again with the next frame: the guest ran on without its vblank meanwhile, and a game could take its disc reads for failed when it came back (Akrido: Ninja Gaiden's dirty disc error after the menu).

## Test build 4 - 2026-10-25

- The core info file names the core "Microsoft - Xbox / Sega Chihiro (xemu)" (NNshi).
- Chihiro: the Chihiro options are in a category of their own, Sega Chihiro, the last one (NNshi).
- Chihiro gun games: new option Sega Chihiro > Light Gun Aim, Mouse or Analog Stick. With the mouse it aims, the left button fires, the right one is the gun's button (House of the Dead III's pump reload, Virtua Cop 3's change weapon, Ghost Squad's action) and the middle one Virtua Cop 3's pedal or Ghost Squad's fire rate, as standalone binds them; RetroArch's light gun still works. With the stick the left stick or D-pad aims, R2 fires, L2 is the gun's button, L the pedal or fire rate and R shoots off the screen. New option Sega Chihiro > Crosshair, on by default: each player's aim drawn over the picture, player 1 red and player 2 blue, where standalone shows the mouse cursor; with one mouse only player 1's (NNshi).
- Vulkan: new option Video > Vulkan Fast Paths (All by default, as standalone), to leave out the pipeline libraries or the dynamic states on a GPU that crashes with one of them (Akrido).
- Vulkan on RetroArch's device: the device is made with the extended dynamic states, vertex input dynamic state, graphics pipeline libraries, host query reset and shader demote where the GPU has them, as standalone's own device is. Without them the renderer's fast paths were off and every new state compiled a whole pipeline while drawing: shader stutters of up to two seconds where standalone barely hitched (NNshi).
- Chihiro: another Chihiro game loads without restarting RetroArch: its image goes into the media board's memory, the last game's backup is written to its save file, and the cabinet, board type, card readers and save file follow the new game. Only a game larger than the media board memory of the first one (Gundam after a 512 MB game) still asks for a restart; an Xbox game after a Chihiro one, or the other way round, too (NNshi).
- Chihiro: new option Sega Chihiro > Force Feedback Rumble, off by default as in standalone, or 25-200%: the drive board's force feedback in OutRun 2 and Maximum Tune rumbles port 1's pad, as standalone gives it to a gamepad (NNshi).
- Vulkan: the picture handed to RetroArch is taken once the game has handled the vblank of that run, which is where it points the display at the frame it just finished. Taken right away, it raced the game: about a quarter of the frames came twice and as many were skipped while the game itself ran at 60 (NNshi: OutRun 2 between 30 and 60 fps, 224 new pictures in 300 runs).
- The log's line every 300 runs has a second one: how many frames the game flipped, when it issued each flip after the vblank it waits for, how long it then waited, and how late the vblank came after RetroArch asked for the frame - for telling a slow game from a late vblank (NNshi: OutRun 2 at about 44 fps where standalone holds 60).
- The core is built on Tovarichtch's xemu fork (main and perf-experimental) in place of mainline xemu: Sega Chihiro emulation (an image that is not an Xbox disc boots a Chihiro), and the fork's tuned guest CPU and NV2A renderer. New options: System > CPU Boost (the fork's native SSE and wider jump cache, on by default) and Video > Smooth First Play (the shaders a game is known to use are compiled while it boots, on by default). The fork's GPU boost is always on in the core: the stock renderer it keeps for it being off has none of the core's frontend handover. The guest's vblank still comes with each retro_run, not from the fork's wall-clock timer, so RetroArch keeps pacing the frames; the fork's Real hardware speed is left off for the same reason (NNshi).
- Chihiro: the cabinet controls are on RetroArch's pads and light guns, per game (README, Chihiro controls), and the Chihiro files are read from `system/xemu/Chihiro/` under MAME's names (NNshi). Chihiro games load as `.bin` netboot images. The machine is built once per RetroArch start, so a Chihiro game after an Xbox one (or the other way round) is refused with a message to restart RetroArch. New option Sega Chihiro > Free Play, on by default (NNshi).
- Reduced Vulkan Buffers is gone: the fork's renderer keeps its inline vertex buffer at 16 MB on every card, smaller than the option's smallest; the depth/stencil conversion buffers still follow the resolution scale.

## Test build 3 - 2026-10-12

- The console's files are also found in `system/` itself, where an older core info file had them, and the BIOS also as `Complex_4627.bin`. `system/xemu/` and `Complex_4627v1.03.bin` stay the documented place and name (boardsofcanada).
- Reduced Vulkan Buffers (Video, on by default): the Vulkan renderer's buffer for inline vertex data is a tenth of xemu's size on every graphics card, as it already was on those with less than 4 GB - about 1.2 GB less video memory and as much less system memory (3.16 to 2.01 GB in NNshi's run, frame times unchanged). Off reserves xemu's size.
- Linux: the core no longer links libX11, so it loads where X11 is absent. The one Xlib function the OpenGL renderer's GLX path called is found at run time, in the frontend's own libX11.
- Every 300 runs the core logs where a run's time went on the shared Vulkan device: how often it ran, how many of the pictures were another frame of the game's, and the time spent waiting for the renderer and in RetroArch's video and audio callbacks.
- A recipe for the libretro buildbot (`.gitlab-ci.yml`): Linux x64, Linux aarch64 and Windows x64, built by the scripts in `.ci/`; the Linux core there has libslirp linked in, as the buildbot ships one file. QEMU's own GitLab CI files are removed. A GitHub workflow replays the jobs in the same images.
- Vulkan on RetroArch's own device: the renderer draws on the device RetroArch makes with the core and each frame is handed over as an image, with no copy between two devices. The core's and RetroArch's frame times are no longer disconnected, and scrolling that was choppy on Vulkan is smooth (tested by NNshi).
- Graphics API option (Video): Vulkan by default, OpenGL as the fallback. Android always uses Vulkan, macOS always OpenGL.
- Aspect Ratio option (Video): Auto, 4:3 or 16:9. Auto follows the console's aspect line, as standalone does; 16:9 is for a game that renders widescreen but is shown squashed.
- Audio paces the core: RetroArch gets one frame of audio per run, and the sound chip waits once about 64 ms is queued.
- Rumble through RetroArch's rumble interface.
- Internal Resolution Scale works on OpenGL: the frame is handed over at the size it was rendered at. The largest picture RetroArch is told to expect follows the scale, so its shader passes are not sized for a resolution that is not in use.
- Closing content stops the emulated console and flushes its disk. Before, the console ran on and was cut off mid-write when RetroArch exited, which could break the hard disk image.
- Another game can be loaded without restarting RetroArch, on Vulkan: the emulated console stays built when content is closed, and the next game puts its disc in the drive, resets the console and starts it again (six games in a row without a crash, tested by NNshi). On OpenGL a second game is still refused with a message. Core options that need a restart, such as the memory size and Graphics API, keep the first game's values until RetroArch is restarted.
- Start Core without content boots the dashboard with an empty tray.
- The core's version names upstream's version and commit and this repository's.
- Vulkan starts on Linux and on GPUs with little memory: the surfaceless EGL display is made in a way libepoxy accepts, and the compute and vertex buffers are sized for the surface scale and the memory there is.
- CI uploads the Linux core unstripped as its own artifact, for profiling and backtraces.
- The core option texts can be translated through libretro's Crowdin project: the options header is on the standard template, with the `intl/` scripts and the upload and sync workflows. All texts are English until the first sync.
- Closing content or RetroArch no longer crashes. The core stays loaded once it has been loaded: QEMU's RCU, vCPU and nv2a threads, which upstream never joins, and its exit handlers ran on code that was no longer there once RetroArch unloaded the core.
- Redump ISOs load. A whole-disc image is attached from its game partition's offset (XGD1, XGD2 or XGD3), found by the XDVDFS volume descriptor; before, the guest was shown the disc's video partition.
- Disc images through the frontend's VFS: a `saf://` or `content://` path, as Android's Play Store RetroArch hands over, is read through RetroArch's VFS, Redump offset included.
- The core logs at start which commit of this repository it was built from.
- The core info file, matching the core, is in every build's zip.

## Test build 2 - 2026-10-07

- Merged up to upstream xemu 0.8.136-53 (478b4f4961), with its changes since February, among them the new DSP with a JIT for the audio processor; on Android, which upstream's prebuilt DSP library does not cover, the core uses the C interpreter. The core reports upstream's version.
- macOS cores, Apple Silicon and Intel. The renderer there is OpenGL, through contexts shared with RetroArch's: MoltenVK has no geometry shaders, which xemu's Vulkan renderer needs.
- The repository holds the core only: the standalone app's UI, packaging and CI are removed (`.upstream-excluded`), and the core is built without SDL. The Xbox Live Communicator headset is not emulated, as it needs SDL audio.
- Linux: the cores load again. The bundled libpcap needed RDMA and D-Bus libraries most systems lack; the core's networking is NAT or off, so the build is without libpcap and carries only libslirp.
- README for the core.
